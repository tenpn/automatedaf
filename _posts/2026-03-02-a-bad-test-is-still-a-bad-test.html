I'm still uncertain on if AI code generation will change game development, but if it does, one thing it'll benefit from is clear and well-written tests. That will let any AI agent generate production code and test it against expectations, without worrying that some important requirement has exited the context window.

At last, those of us who have been calling for years for fast feedback loops and rigorous safety nets might have our time in the sun!

But if tests are important, we can just get the AI agents to write their own tests, right?

Not so fast. Although this may very well be exceptionalism on my part, I think these next few years are going to see people having to level up their knowledge of good automated testing practice.

A bad test is still a bad test - costing you time and resources as it executes, being so fragile that it needs constant maintenance, and failing non-deterministically with false positives and false negatives. If you don't know what to prompt for, you'll get all these kinds of tests and more out of the agent.

After all, test automation enthusiasts have been banging the drum for years that your test code is as important as your production code. People like Roy Osherove argue it's even more important - you'll read tests more often, update them more often, and they'll execute on the server more often.

So I think if you're concerned about how games programming might change as a profession, brush up on your test automation best practices. And if the bubble bursts and things go back to how they always were, then you'll still have a very useful skill.

Happy testing!
