Here's a quick example of using Spec in Unreal 5 to make Asset Tests:

Let's say we have a folder of our unreal project that contains meshes for prototyping a level layout. We want those meshes to always have navmesh data, so agents can pathfind around them.

This is an awkward thing for QA to test, because it requires either specialist tools or tediously kiting enemies around each unique asset instance in a level.

It's trivial for a computer to validate this data, but we don't know ahead of time what the assets are called! We only know they live in a specific project folder.

We can use Spec https://dev.epicgames.com/documentation/en-us/unreal-engine/..., part of Unreal's Automation Framework, to iterate all the assets and make one test suite per asset. When an asset is missing nav data, we'll get a specific actionable test failure, allowing us to fix the problem quickly.

The magic is happening on lines 18-20, where we for-loop through some assets and then call Describe(), which starts a new test suite. You can even nest these, having Describes() inside Describes() inside Describes().

The wonderful thing is, this happens at editor boot, so the CI server can see new assets the moment they are committed. A whole class of bug will no longer make it to QA builds. No need to wait for a programmer to manually update a list.

Happy testing!
